# PostgreSQL Backup to Telegram

Интерактивный Bash-скрипт для автоматического резервного копирования и восстановления баз данных PostgreSQL, запущенных в Docker, с отправкой архивов в Telegram и управлением расписанием через `systemd.timer`.

## Возможности

* **Интерактивный TUI-интерфейс** — навигация стрелками (`↑`/`↓`, `j`/`k`, цифры), карточка статуса, спиннер с таймером и скрытый ввод токена без сторонних зависимостей.
* **Сжатие на лету и проверка целостности** — `pg_dump --clean --if-exists | gzip -6` без создания промежуточных несжатых `.sql`-файлов, с последующей проверкой `gzip -t`.
* **Отправка в Telegram** — автоматическая разбивка архивов больше 50 МБ на части по 49 МБ, 3 попытки отправки при сетевых сбоях и тест подключения из меню.
* **Гибкое расписание через `systemd.timer`** — запуск по точному времени (`03:00`, `03:00 15:00`) или с заданным интервалом в часах, мгновенная пауза и возобновление.
* **Локальное хранение и ротация** — копии хранятся на сервере заданное число дней (по умолчанию `7`, `0` — удалять сразу после отправки). При сбое отправки в Telegram архив не удаляется.
* **Восстановление в один клик** — выбор из локальных копий или указание пути к файлу `.sql` / `.sql.gz` вручную.
* **Надёжность** — защита от параллельного запуска через `flock`, раздельные логи с ротацией (5 МБ) и автоматическим скрытием токена бота.
* **Самообновление** — проверка и установка новых версий с GitHub без потери конфигурации.

---

## Требования

* Linux с `systemd` и `bash` (4.0+)
* `docker`, `curl`, `gzip`
* Права `root` (для настройки `systemd` и создания команды `pg-backup`)

## Установка и первый запуск

Запускать можно из **любой** директории:

```bash
curl -fsSL [https://raw.githubusercontent.com/sooqa1nya/pg_backup/master/pg-backup.sh](https://raw.githubusercontent.com/sooqa1nya/pg_backup/master/pg-backup.sh) -o /tmp/pg-backup.sh \
  && chmod +x /tmp/pg-backup.sh \
  && /tmp/pg-backup.sh \
  && rm -f /tmp/pg-backup.sh
```

При первом запуске скрипт автоматически:
1. Скопирует себя в `/opt/pg-backup-tg/pg-backup.sh`.
2. Создаст глобальную команду `/usr/local/bin/pg-backup`.
3. Запустит мастер настройки: запросит токен бота (`@BotFather`), `Chat ID`, имя Docker-контейнера, `DB_USER`, `DB_NAME`, срок локального хранения и расписание.

> **Важно:** не запускайте скрипт через пайп `curl ... | bash` — для работы интерактивного меню и самоустановки необходим локальный файл и прямой ввод с терминала.

## Использование

### Интерактивное меню

После установки просто выполните из любой директории:

```bash
pg-backup
```

### Команды CLI

Скриптом можно управлять напрямую без входа в меню:

| Команда | Описание |
| :--- | :--- |
| `pg-backup` | Открыть интерактивное меню |
| `pg-backup backup` | Выполнить моментальный бэкап |
| `pg-backup restore` | Запустить мастер восстановления БД |
| `pg-backup pause` | Приостановить автоматические бэкапы |
| `pg-backup resume` | Возобновить автоматические бэкапы |
| `pg-backup status` | Показать карточку текущего состояния |
| `pg-backup update` | Проверить и установить обновление с GitHub |
| `pg-backup uninstall` | Полностью удалить скрипт, таймер и конфиг |

## Восстановление из бэкапа

Выполните `pg-backup restore` (или выберите пункт **2** в меню):

* Если на сервере есть локальные копии в `/opt/pg-backup-tg/backups`, они отобразятся в списке (от новых к старым).
* Если нужно восстановиться из файла, скачанного из Telegram, выберите пункт **`P`** и укажите полный путь к `.sql.gz` или `.sql`.

> **Если архив был разбит на части (> 50 МБ):** скачайте все части `.part_*` из Telegram в одну папку и склейте их перед восстановлением:
> ```bash
> cat dbname_2026-01-01_03-00-00.sql.gz.part_* > backup.sql.gz
> ```

## Структура файлов

```text
/opt/pg-backup-tg/
├── pg-backup.sh            # Исполняемый скрипт
├── config.env              # Конфигурация (права 600)
├── backups/                # Локальные архивы (.sql.gz)
└── logs/
    ├── backup.log          # Лог создания и отправки бэкапов
    ├── restore.log         # Лог восстановлений
    ├── error.log           # Предупреждения и ошибки
    └── system.log          # Системные события

/usr/local/bin/pg-backup    # Симлинк для быстрого запуска
/etc/systemd/system/
├── pg-backup-telegram.service
└── pg-backup-telegram.timer
```

Проверка расписания и журнала `systemd` вручную:

```bash
systemctl list-timers pg-backup-telegram.timer
journalctl -u pg-backup-telegram.service -n 50
```

## Обновление и удаление

**Обновление** (конфигурация `config.env` и локальные бэкапы сохраняются):

```bash
pg-backup update
```

**Полное удаление** скрипта, симлинка, `systemd`-юнитов и рабочей папки:

```bash
pg-backup uninstall
```
